# OpenSeaBri Owner Deployment Checklist

Single-page executable checklist. Commands are exact. Keep live providers disabled for the first deploy. Do not paste secrets into chat.

---

## Pre-Flight (run locally before any cloud work)

- [ ] `npm run owner:next` — prints what env vars are missing in the current shell
- [ ] `npm run deployment:preflight` — confirms the local package is ready
- [ ] `npm run release:check` — final release gate check
- [ ] `npm run check:secrets` — confirms no secrets are hardcoded
- [ ] `npm run secret-scan` — confirms no secrets in source files

---

## 1. Provision Host

Choose one. Each has a deployment guide in `docs/deployment/providers/`.

**Render (recommended for first deploy — dashboard-driven):**
- Use `render.yaml` Blueprint: Render dashboard → New → Blueprint → connect repo → select `render.yaml`
- Full guide: `docs/deployment/providers/RENDER_DEPLOYMENT_GUIDE.md`

**Railway:**
- Use `railway.json`: Railway dashboard → New Project → connect repo
- Full guide: `docs/deployment/providers/RAILWAY_DEPLOYMENT_GUIDE.md`

**Fly.io:**
```bash
fly launch --config fly.toml
```
- Full guide: `docs/deployment/providers/FLY_DEPLOYMENT_GUIDE.md`

**Docker (self-hosted):**
```bash
docker compose up --build
```
- Includes local Postgres via `docker-compose.yml`

---

## 2. Create Managed Postgres

**Render:** Blueprint creates it automatically from `render.yaml`.

**Railway:** Add a PostgreSQL plugin in the Railway project dashboard.

**Fly.io:**
```bash
fly postgres create --name openseabri-db --region iad
fly postgres attach openseabri-db --app openseabri
```

**After creation:** Copy the connection URL into your host's secret manager as `SEABRI_DATABASE_URL`. Do not paste it into chat.

---

## 3. Set Production Secrets

Full list: `docs/deployment/OPENSEABRI_OWNER_MANUAL_ACTIONS.md`

Minimum required in your host's secret manager:

| Secret | Notes |
|---|---|
| `OPENSEABRI_MODE` | Set to `production` |
| `OPENSEABRI_API_KEY` | Auto-generated by Render blueprint; generate manually on other hosts |
| `SEABRI_WS_TOKEN` | Auto-generated by Render blueprint; generate manually on other hosts |
| `OPENSEABRI_CANVAS_WS_TOKEN` | Auto-generated by Render blueprint; generate manually on other hosts |
| `OPENSEABRI_CORS_ORIGIN` | Exact frontend origin, e.g. `https://app.yourdomain.com` |
| `SEABRI_DATABASE_URL` | From managed Postgres (step 2) |
| `OPENSEABRI_PERSISTENCE_ADAPTER` | Set to `database` |
| `OPENSEABRI_TELEMETRY_STORE` | Set to `database` |
| `OPENSEABRI_RATE_LIMIT` | Recommended: `120` |
| LLM provider key | Required for gateway model calls — see `docs/deployment/OPENSEABRI_OWNER_MANUAL_ACTIONS.md` |
| `OPENSEABRI_CHANNELS_ENABLED` | Leave empty for first deploy |
| `OPENSEABRI_LIVE_PROVIDER_APPROVED` | Set to `false` for first deploy |

**Fly.io secret setting pattern:**
```bash
fly secrets set OPENSEABRI_API_KEY=<value> --app openseabri
fly secrets set SEABRI_WS_TOKEN=<value> --app openseabri
# ... repeat for each secret
```

---

## 4. Deploy and Run Migrations

**Deploy:**
```bash
# Render/Railway: deploy triggered by git push or dashboard button
# Fly.io:
fly deploy --app openseabri
```

**Run migrations against live DB (one-time, after first deploy):**
```bash
# In a one-off shell with production secrets present:
npm run db:migrate
```

**Verify tables exist:**
```bash
OPENSEABRI_DB_CONNECT_CHECK=true npm run db:migration-check
```

Full migration guide: `docs/deployment/OPENSEABRI_DATABASE_MIGRATION_RUNBOOK.md`

---

## 5. DNS Configuration

Full guide: `docs/deployment/OPENSEABRI_GODADDY_DNS_GUIDE.md`

Summary:
- Create `app.<yourdomain>` CNAME → your host's public URL
- Create `api.<yourdomain>` CNAME → your host's public URL (or separate gateway service)
- Wait for DNS propagation (up to 24 hours; usually under 1 hour)

---

## 6. Verify Deployment

```bash
# Replace with your actual deployed gateway URL
export OPENSEABRI_BASE_URL=https://api.<yourdomain>
export OPENSEABRI_API_KEY=<your-production-api-key>
npm run check:operational
```

All checks must pass (health, registry, provider readiness, demo endpoint, canvas).

Then run the full hosted smoke:
```bash
npm run smoke:staging
```

---

## 7. Provider Approval (one at a time, after step 6 passes)

**Check readiness for a provider:**
```bash
npx tsx scripts/approve-provider.ts telegram
npx tsx scripts/approve-provider.ts whatsapp
npx tsx scripts/approve-provider.ts sms
npx tsx scripts/approve-provider.ts voice
npx tsx scripts/approve-provider.ts vision
```

**Enable a provider after its smoke test passes:**
```bash
# Add the provider to the host's secret: OPENSEABRI_CHANNELS_ENABLED=telegram
# Keep OPENSEABRI_LIVE_PROVIDER_APPROVED=false until all provider smoke tests pass
```

Full provider validation plan: `docs/testing/OPENSEABRI_LIVE_PROVIDER_VALIDATION_PLAN.md`

---

## 8. Open Pilot Traffic

Open pilot traffic only after:

- [ ] All deployment steps above are checked
- [ ] DB tables verified in staging logs
- [ ] `npm run check:operational` passes against deployed host
- [ ] DNS and TLS working
- [ ] Logs and alerts are active on your host
- [ ] Each enabled provider has passed its safe-target smoke test

## Quick Reference — npm Scripts

| Script | Purpose |
|---|---|
| `npm run owner:next` | Print what's missing for production |
| `npm run deployment:preflight` | Final local code readiness check |
| `npm run release:check` | Release gate |
| `npm run db:migrate` | Run DB migrations |
| `npm run db:migration-check` | Verify tables exist |
| `npm run check:operational` | Smoke against a deployed gateway |
| `npm run smoke:staging` | Full staging smoke (requires deployed host) |
| `npx tsx scripts/approve-provider.ts` | Provider approval readiness check |
